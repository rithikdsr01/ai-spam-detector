    About the AI Model & Algorithms

    A deep-dive into the Natural Language Processing pipeline and Naive Bayes mathematics.

    1. TF-IDF Feature Extraction

    Machine learning algorithms cannot process raw text strings directly. TF-IDF (Term Frequency – Inverse Document Frequency) converts text into numerical vectors reflecting word significance.

    TF-IDF(t, d, D) = TF(t, d) × ln[(1 + |D|) / (1 + DF(t))]

    • TF(t, d) measures frequency of term t in document d.
    • IDF(t, D) penalizes ubiquitous words (like "the", "and") while rewarding high-discriminative tokens (like "prize", "urgent", "claim").
    • Bigrams ngram_range=(1,2) capture word pairs such as "cash prize" and "gift card".

    2. Multinomial Naive Bayes

    Multinomial Naive Bayes is a probabilistic classifier grounded in Bayes' Theorem with the naive assumption of conditional word independence.

    P(Spam | W) ∝ P(Spam) × ∏ P(wᵢ | Spam)

    • Calculates the posterior probability of a class given feature words.
    • Employs Laplace smoothing (alpha=0.2) to prevent zero-probability errors when encountering rare terms.
    • Ideal for high-dimensional, sparse text classification due to lightning-fast inference and low memory footprint.

    3. Multimodal Vision Forensics (Gemini & Groq)

    For transaction receipts, image classification goes beyond text. Google Gemini Vision and Groq API inspect:

    • Typography & Font Consistency: Detects pasted numbers or mismatched font rendering on transaction amounts.
    • Layout Alignment & Compression: Discovers localized JPEG artifacts and anti-aliasing discrepancies.
    • Banking Protocol Syntax: Verifies 12-digit Indian UPI UTRs, SWIFT, PayPal, and Stripe transaction ID structures.
    • Spoof APK Signatures: Flags templates generated by offline mock payment apps (e.g. Paytm Spoof APK).

    5. Project Objectives & Impact

    SMS smishing and fake payment receipt fraud cause billions of dollars in annual merchant losses worldwide. The objectives of this platform are:

    • Provide accessible, real-time protection for messages and payment receipts.
    • Deliver model interpretability by displaying influential trigger keywords and visual forensic checks.
    • Maintain historical audit trails and analytical intelligence via persistent SQLite storage.
    • Offer zero-configuration container-friendly deployment for cloud platforms like Render.

    Deploy to Render

    Step-by-step instructions to deploy this web application to Render's free tier cloud hosting.

    1 Push Code to GitHub

    Initialize a git repository, commit all project files, and push to your GitHub account:

    git init
    git add .
    git commit -m "Initial commit: AI Spam Message Detector & Receipt Scanner"
    git branch -M main
    git remote add origin https://github.com/YOUR_USERNAME/ai-spam-detector.git
    git push -u origin main

    2 Create a Web Service on Render

    1. Go to Render.com and sign in with GitHub.
    2. Click "New +" and select "Web Service".
    3. Choose your repository ai-spam-detector and connect.

    3 Configure Build & Start Commands

    Render will ask for service settings. Fill them in as follows:

    • Name: ai-spam-detector
    • Environment: Python 3
    • Region: Select closest region (e.g. Frankfurt, Oregon, Singapore)
    • Branch: main
    • Build Command: pip install -r requirements.txt
    • Start Command: gunicorn app:app
    • Environment Variables (Optional): GEMINI_API_KEY and GROQ_API_KEY

    4 Deploy & Go Live!

    Click "Create Web Service". Render will install dependencies from requirements.txt and launch Gunicorn. In 1-2 minutes, your live URL (e.g. https://ai-spam-detector.onrender.com) will be running!
